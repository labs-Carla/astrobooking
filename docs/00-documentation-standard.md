---

# 1. Objetivo

Este documento define los estándares de documentación utilizados en el proyecto AstroBooking.

Su propósito es garantizar consistencia, legibilidad y mantenibilidad en toda la documentación técnica y funcional del proyecto.

---

# 2. Estructura de los documentos

Todos los documentos deberán seguir la siguiente estructura cuando aplique:

1. Título
2. Información del documento
3. Tabla de contenido
4. Introducción
5. Desarrollo
6. Conclusiones (opcional)
7. Referencias (opcional)

---

# 3. Convenciones de nombres

Los documentos utilizarán nombres en inglés, en minúsculas y separados por guiones.

Ejemplos:

- 00-documentation-standard.md
- 01-product-vision.md
- 02-functional-requirements.md
- 03-non-functional-requirements.md
- 04-user-stories.md

---

# 4. Encabezados

Se utilizará la siguiente jerarquía:

# Nivel 1

## Nivel 2

### Nivel 3

#### Nivel 4

No deberán utilizarse más de cuatro niveles de encabezados.

---

# 5. Tablas

Las tablas deberán utilizarse para:

- Requerimientos
- Actores
- Roles
- Responsabilidades
- Matrices
- Trazabilidad

---

# 6. Diagramas

Todos los diagramas deberán almacenarse en:

docs/diagrams/

Los archivos fuente utilizarán el formato Draw.io.

---

# 7. Idioma

La documentación del proyecto será redactada en español.

Los nombres técnicos, tecnologías, patrones de diseño y términos ampliamente aceptados podrán mantenerse en inglés.

Ejemplos:

- Spring Boot
- REST API
- JWT
- Docker
- Clean Architecture

---

# 8. Versionado

Cada documento deberá incluir:

- Versión
- Estado
- Autor
- Fecha

Estados permitidos:

- Draft
- In Review
- Approved
- Deprecated

---

# 9. Principios

Toda la documentación deberá ser:

- Clara
- Consistente
- Verificable
- Actualizable
- Orientada al negocio antes que a la implementación

---

# 10. Mantenimiento

Cada documento deberá actualizarse cuando exista un cambio funcional o arquitectónico que modifique su contenido.
